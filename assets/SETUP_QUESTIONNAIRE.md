# 使用者首次設定問卷

請先回答以下問題，再建立 `config.yaml`。第一次執行建議只產生唯讀報告，不要直接寫入外部系統。

## A. 你想解決哪些工作情境？

請勾選需要的情境：

- [ ] 日常工作執行
- [ ] 提醒 / 後續跟進
- [ ] 重要會議決策記錄
- [ ] 會議待辦追蹤
- [ ] 產品新功能需求
- [ ] 產品改善
- [ ] Bug / Debug

## B. 資料來源

1. 聊天記錄所在路徑：
2. 文件類型：TXT / JSON / HTML / CSV / 其他
3. 是否包含子目錄：是 / 否
4. 是否允許跟隨 symbolic link / junction：建議否
5. 單一檔案最大可接受大小：
6. 資料是否由本機應用持續更新：是 / 否
7. 此資料是否包含公司機密、客戶資料或個資：是 / 否 / 不確定

## C. 群組範圍

1. 群組標題必須包含哪些字樣？
2. 多個字樣是「任一符合」還是「全部符合」？
3. 哪些群組必須排除？
4. 是否限制特定發送者？
5. 是否限制訊息內容關鍵詞？
6. 哪些群組絕對不可讀取？

## D. 時間範圍

1. 首次運行檢查過去多少小時？
2. 後續是否從上次成功執行時間繼續？
3. 是否需要重疊檢查最近若干分鐘？

## E. 工作與會議規則

1. 「提醒我」「之後追一下」是否只列入報告，還是需要後續串接真正提醒工具？
2. 會議中的「建議 / 考慮 / 可能」是否一律不得視為已確認決策？建議是。
3. 若沒有明確 Owner，是否保持空白？建議是。
4. 若沒有明確 Due Date，是否保持空白？建議是。
5. 哪些會議群組屬於重要決策來源？

## F. 產品開發規則

1. 是否使用預設類別？
   - New Feature
   - Improvement
   - Bug / Debug
2. 哪些產品類別允許未來寫入 Backlog？
3. 哪些類別必須人工確認？
4. Bug 是否要求重現步驟才可寫入？
5. 新功能是否要求 Current / Expected Behavior 或 Acceptance Criteria？

## G. 歷史資料與去重

1. 歷史日報存放在哪裡？
2. 是否有既有需求/任務清單？
3. 是否已建立本地索引？
4. 目的系統是否可查詢既有事項？
5. 哪些資料禁止上傳到公開倉庫？

5. 是否需要首次人工登入？
6. 是否允許同一執行環境復用登入狀態？
7. 哪些類別明確允許寫入？

## J. 隱私與遮罩

1. 是否需要隱藏發送者姓名？
2. 是否需要遮罩 Email / Phone / Account ID？
3. 原始上下文最多保留多少字元？建議 500 或更少。
4. 是否禁止整段聊天貼入 Ticket？建議是。
5. 若訊息中出現 Password / Token / Cookie / OTP，是否一律遮罩並禁止寫入？應為是。

## K. 寫入安全規則

1. 首次運行只預覽還是允許寫入？建議只預覽。
2. 是否只寫入確認全新的事項？建議是。
3. 相似事項是否只放入日報？建議是。
4. 既有事項補充是否允許自動更新？預設否。
5. 遇到不明確結果時是否停止寫入？應為是。
6. API 回傳不明時是否先查詢再重試？應為是。
